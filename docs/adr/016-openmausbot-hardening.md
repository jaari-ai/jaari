# ADR-016: Hardening borrowed from OpenMausBot: dispatch re-check, chained audit, resolve-check-dial egress, owner hold

- **Status:** Accepted
- **Extended by:** [ADR-055](055-takeover-transport.md), [ADR-077](077-subscription-cli-engines.md), [ADR-080](080-egress-core-in-phase-0.md)
- **Date:** 2026-11-10

## Decision
`refs/openmausbot` (Apache-2.0, commit in `refs/INDEX.md`) is a fourth design reference. Jaari keeps its architecture and adopts seven mechanisms that make existing ADRs more precise. Study and sources: `docs/learning/09-openmausbot.md`. **1. Re-check at dispatch (extends ADR-006).** After the digest matches, the executor re-reads the state the approval depended on (capability installed and enabled, standing policy, connected-account scope, kill switch, shadow mode) and refuses if any of it changed since the approval. The digest proves the action is the one approved; the re-check proves the world still allows it. **2. Unreadable is not clear (extends ADR-006, principle 9).** Any deterministic classifier in the gate path (shell lexer, page heuristics of OQ-30, MCP tool classification) has three results: clear, flagged, unreadable. Unreadable is treated as flagged and goes to the owner. **3. Hash-chained audit (extends ADR-006).** Each `audit.jsonl` row carries the SHA-256 of the previous row, plus the rule that decided, the actor (owner on which channel, standing grant, policy), whether the owner was present, and the medium (tap, text, voice). Writes are synchronous: an action whose audit row cannot be written does not run. **4. Restart rule.** A turn cut by a crash or restart is rerun at most once, and never if the audit log shows an effectful action started in it; that turn is reported to the owner instead. Whether a provider call may be retried is decided from protocol state (accepted or not), never from error text. **5. Resolve, check, dial (extends `@jaari/http`, ADR-012).** The egress gate resolves a name itself, classifies every returned address against one address-class table (cloud metadata, link-local, loopback, private ranges, multicast, benchmark ranges; NAT64 and 6to4 unwrapped first), and connects only to the addresses it checked, which closes DNS rebinding and redirects to private hosts. The same table serves the HTTP client, the browser, and sandboxes. The browser reaches the network only through a per-session loopback SOCKS5 listener, with Chromium's loopback bypass removed and non-proxied WebRTC UDP disabled. The daemon's own listening ports are always denied. **6. Secret hygiene (extends ADR-007).** A resolved secret is registered with a scrubber that removes its exact value, and common encodings of it, from tool results, logs, and screenshots' text before anything reaches the model or disk. The model names a credential by a typed target id, never by path or URL. While a filled secret is on a page, screenshots and page evaluation are refused until the field is cleared. **7. Owner hold (extends ADR-005).** Takeover is a hold that belongs to the owner, not to one window or device. On take, new agent calls are refused and already accepted ones drain; while held, agent input is refused, never queued; the hold ends on release, two minutes after the owner's last view closes, or after five idle minutes. Transport stays OQ-34. **Reuse.** OpenMausBot is studied for design. Copying code from it is allowed only outside its `enterprise/` directory (source-available, not Apache), keeps the Apache-2.0 header and NOTICE text for the copied file, and gets a `NOTICE` entry with path and commit, as ADR-014 requires. Parts it adapted from MIT projects (its egress gate from T3 Code) are taken from the upstream project.

## Alternatives rejected
Adopting its approval model (approval bound to a request id, cards truncated at 400 characters, Full access as the default, the provider's LLM reviewer deciding at Approve-for-me: all weaker than ADR-006 and against principle 9); detecting outbound actions from verbs in tool names (Jaari maps every tool to a declared capability); its roster of bots, rooms, and Chief of Staff (multi-agent product shape, a v1 non-goal); driving vendor CLIs as the main loop (ADR-001; allowed only for sandboxed children, ADR-077); a hosted relay, hosted Composio broker, and vendor cloud desktop (not self-hosted); its event log as an audit record (lossy by design: drops on overflow, fire-and-forget writes); a decision model that fails open (Jaari's local-only roles fail closed, ADR-011); amending ADR-005, 006, 007 in place (they are accepted; this ADR records the additions so the owner can accept or reject them as a set).

## Amendments
- **ADR-055:** decides the takeover transport that point 7 left open ("Transport stays OQ-34"); the hold rules are unchanged.
- **ADR-077:** own-loop coding CLIs are allowed only as sandboxed children.
- **ADR-080 (resolves OQ-68):** the resolve-check-dial core and the address-class table ship in
  Phase 0, and every outbound call uses them from the start; a lint rule refuses other network
  clients.
